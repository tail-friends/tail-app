# 캐릭터 공통 계약 초안

## 목적과 적용 범위

Android와 iOS가 같은 사육 개체의 캐릭터를 같은 속성과 행동 상태로 표현하기 위한
플랫폼 중립 규칙을 정의한다. 실제 캐릭터 JSON 필드, Rive 파일과 State Machine
이름은 현재 확인되지 않았으므로 이 문서에서 확정하지 않는다.

## 계층 분리

- **CONFIRMED**: 캐릭터 속성 데이터, 행동 로직과 렌더러를 서로 분리한다.
- **CONFIRMED**: 첫 2D 렌더러는 향후 다른 렌더러로 교체할 수 있어야 한다.
- **PROPOSED**: 공통 데이터 모델은 플랫폼 UI 타입, Swift/Flutter 클래스, 파일 경로와
  애니메이션 엔진 객체를 포함하지 않는다.
- **PROPOSED**: 행동 결정기는 공통 행동 상태를 출력하고 각 플랫폼 렌더러가 이를
  해당 애니메이션으로 매핑한다.

```text
서버 캐릭터 데이터 → 플랫폼 중립 속성/행동 → 플랫폼 렌더러 → 화면
```

## 공통 속성 표현

종, 색상, 무늬와 체형은 표시 문자열이나 색상 hex 대신 합의된 안정적 code로 표현하는
방식을 **PROPOSED**한다. 화면용 이름, 현지화 문구, 실제 색과 에셋 매핑은 렌더러 또는
표시 계층이 담당한다.

| 속성 | 공통 의미 | 미정 사항 |
|---|---|---|
| 종 | 캐릭터 기반 형태 | 지원 종 code와 버전 |
| 색상 | 기본 색상 변형 | 허용 code와 조합 규칙 |
| 무늬 | 표면 패턴 변형 | 허용 code와 종별 제약 |
| 체형 | 몸체 형태 변형 | 허용 code와 단계 |

정확한 JSON 필드, code 목록, 필수 여부와 유효한 조합은 **OPEN**이다. 확정 전에는
플랫폼별 enum을 공통 계약처럼 배포하지 않는다.

## 저장과 불러오기

- **PROPOSED**: 백엔드가 사용자·사육 개체에 연결된 캐릭터 속성의 기준 원본을 보관하고,
  Android와 iOS는 같은 서버 데이터를 렌더링한다.
- **PROPOSED**: 저장 성공을 서버가 확인하기 전에는 다른 기기에 동기화됐다고 표시하지
  않는다.
- **PROPOSED**: 캐시는 오프라인 표시를 위한 복사본이며 서버 기준 데이터를 임의로
  덮어쓰지 않는다.
- **PROPOSED**: 데이터에 schema version 또는 그에 준하는 호환성 식별 방법을 둔다.
- **OPEN**: 저장 API, 충돌 해결, 캐시 수명, 오프라인 수정과 버전 필드 형식은 Backend·
  Android·iOS가 확정해야 한다.

## 행동 상태와 전환

행동 상태는 아래 여섯 개를 그대로 유지한다.

- `IDLE`
- `WALK`
- `CHASE`
- `EAT`
- `REACT`
- `SLEEP`

- **CONFIRMED**: 상태 이름을 플랫폼별 이름으로 바꾸거나 추가 상태로 대체하지 않는다.
- **PROPOSED**: 서버가 행동 상태를 전달하는 경우 알 수 없는 값은 크래시시키지 않고
  안전한 기본 표현으로 처리한다.
- **PROPOSED**: 애니메이션 전환 중 새 상태가 오면 각 플랫폼은 같은 우선순위 정책을
  적용해야 한다.
- **OPEN**: 상태 전환표, 우선순위, 반복 여부, 재생 시간, 이벤트에 따른 상태 선택과
  기본 표현을 `IDLE`로 할지는 캐릭터 기획과 양 플랫폼이 확정해야 한다.

전환 정책 확정 전에는 플랫폼 고유의 상태 우선순위를 공통 동작으로 간주하지 않는다.

## Rive 에셋

- **PROPOSED**: 동일한 `.riv` 파일은 라이선스와 빌드 조건이 허용하면 양 플랫폼에서
  공유할 수 있다.
- 각 플랫폼은 지원 Rive 런타임 버전, 로드 성공, 렌더링 크기, 색상, State Machine
  입력과 성능을 별도로 검증해야 한다.
- **OPEN**: 실제 Rive 파일, artboard, State Machine, input 이름, 런타임 버전과 배포
  방식은 아직 확인되지 않았다.

이 항목이 확정되기 전에는 문자열 이름을 코드에 하드코딩하거나 Rive 기반 구현을
완료로 처리하지 않는다.

## 누락과 로딩 실패

- **PROPOSED**: 캐릭터 속성 일부가 없거나 알 수 없는 code이면 앱이 종료되지 않는
  중립 placeholder를 표시하고 편집 또는 재시도 경로를 제공한다.
- **PROPOSED**: 네트워크 로딩 중에는 이전에 검증된 캐시가 있으면 사용할 수 있으며,
  없으면 로딩 상태를 표시한다.
- **PROPOSED**: 에셋 로드 실패와 서버 데이터 오류를 구분해 진단하되 사용자에게 내부
  파일명이나 서버 원문을 노출하지 않는다.
- **OPEN**: 공식 placeholder 디자인, 부분 데이터의 기본값, 재시도 횟수와 캐시 정책은
  제품·디자인·양 플랫폼이 확정해야 한다.

## 렌더러 교체와 호환성

- 공통 속성과 행동 code는 특정 렌더러의 레이어명이나 animation name과 분리한다.
- 새 렌더러는 지원하는 schema version과 code 집합을 선언하고 이전 데이터를 변환하거나
  안전한 대체 표현을 제공한다.
- 서버 데이터의 알 수 없는 필드를 읽지 못한다는 이유로 전체 캐릭터를 삭제하지 않는다.
- **OPEN**: schema version 정책, migration 책임과 구버전 앱 지원 기간은 Backend와 양
  플랫폼이 확정해야 한다.

## 사진 원본과 동의

- **CONFIRMED**: 사진 분석 목적을 먼저 안내하고, 원본 보관은 사용자의 명시적 동의를
  받은 경우에만 허용한다.
- **CONFIRMED**: 동의를 철회하거나 원본을 삭제할 수 있는 경로를 제공해야 한다.
- **CONFIRMED**: AI 또는 Backend 인증키를 모바일 앱에 포함하지 않는다.
- **PROPOSED**: 분석 동의와 원본 보관 동의를 분리하고, 보관하지 않는 선택이 캐릭터의
  기본 사용을 부당하게 막지 않도록 한다.
- **OPEN**: 보관 기간, 저장 위치, 파생 이미지 포함 삭제 범위, 백업 삭제 시점과 동의
  이력 보존은 제품·Backend·개인정보 담당자가 결정해야 한다.

보관·삭제 정책 확정 전에는 원본 사진의 서버 영구 보관을 구현하지 않는다.
