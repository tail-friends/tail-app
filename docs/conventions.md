# 협업 규칙

## 브랜치와 PR

- `main`: 정식 배포
- `develop`: 개발 통합
- 작업: `feat/#번호-기능명`, `fix/#번호-기능명`, `chore/#번호-작업명`, `docs/#번호-문서명`, `refactor/#번호-작업명`
- 모든 기능과 작업은 Issue를 먼저 확인한다.
- 작업 PR의 기본 대상은 `develop`이며, `develop`에서 `main`으로는 릴리스 PR을 사용한다.
- 코드 리뷰와 필수 검증을 통과한 뒤 병합한다.

## 커밋

Gitmoji와 한국어 요약을 사용한다. 한 커밋은 한 가지 논리적 변경을 담는다.

예: `🏗️ 프로젝트 초기 개발 환경 구축`

## 코드 소유 영역

- Android 담당: `android-app/`
- iOS 담당: `ios-app/`
- 공통: `shared/`, `docs/`, `.github/`
- 백엔드: 별도 저장소

공통 영역 변경 시 Android와 iOS 영향을 모두 확인한다. 다른 담당자의 영역은
명시적 합의 없이 수정하지 않는다.

## 품질과 안전

- 기존 사용자 변경을 삭제하거나 초기화하지 않는다.
- 테스트 실패나 미실행을 성공으로 보고하지 않는다.
- 비밀정보와 개인정보를 커밋하거나 출력하지 않는다.
- 불필요한 리팩터링, 미사용 추상화, 과도한 파일 생성을 피한다.
- API 규격과 제품 결정을 추측하지 않고 미정 항목으로 기록한다.
