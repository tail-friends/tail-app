# 사육 데이터 공통 계약 초안

## 목적과 적용 범위

Android와 iOS가 같은 사육 개체와 기록을 같은 의미로 생성·조회·수정·삭제하도록
도메인 규칙을 정의한다. 아래 데이터 항목은 개념 모델이며 API 필드명이나 DB 스키마가
아니다. 실제 전송 계약은 Backend 검토 후 별도로 확정한다.

## 확정된 급여 규칙

- **CONFIRMED**: 다음 급여일은 `마지막 정상 급여일 + 급여 주기`로 계산한다.
- **CONFIRMED**: 급여 거부는 마지막 정상 급여일을 갱신하지 않는다.
- **CONFIRMED**: 급여 상태는 `NO_RECORD`, `UPCOMING`, `DUE`, `OVERDUE`만 사용한다.

상태 의미는 다음과 같이 제안하며 경계 시각은 날짜·시간 정책 확정이 필요하다.

| 상태 | 공통 의미 |
|---|---|
| `NO_RECORD` | 다음 급여일 계산에 사용할 정상 급여 기록이 없음 |
| `UPCOMING` | 다음 급여일이 아직 도래하지 않음 |
| `DUE` | 기준 날짜가 다음 급여일과 같음 |
| `OVERDUE` | 기준 날짜가 다음 급여일을 지남 |

급여 주기가 없거나 유효하지 않으면 임의 기본값으로 계산하지 않고 `NO_RECORD` 또는
별도 검증 오류 중 하나를 선택해야 한다. 이 선택은 **OPEN**이다.

## 공통 개념 모델

| 개념 | 필요한 의미 | 상태 |
|---|---|---|
| 사육 개체 | 서버 식별자, 이름, 종, 부화·입양 관련 날짜, 급여 주기, 캐릭터 연결 | 세부 필드 **PROPOSED/OPEN** |
| 급여 기록 | 대상 개체, 발생 시각, 정상 급여 또는 거부, 먹이 설명·양 선택 입력 | 결과 표현 **PROPOSED** |
| 탈피 기록 | 대상 개체, 발생 날짜·시각, 완료 여부 또는 메모 선택 입력 | 세부 상태 **OPEN** |
| 체중 기록 | 대상 개체, 측정 시각, 양수 값, 단위 | 기준 단위 **PROPOSED** |
| 공통 기록 정보 | 서버 식별자, 생성·수정 시각, 작성 주체 또는 동기화 버전 | Backend 계약 **OPEN** |

종 목록, 필수·선택 필드, 문자열 길이, 급여 주기 허용 범위와 개체 삭제 시 기록 처리
방식은 제품·Backend 합의 전까지 확정하지 않는다.

## 개체 등록과 수정

- **PROPOSED**: 앱은 제출 전에 공백만 있는 필수 텍스트, 유효하지 않은 날짜와 범위를
  검증하며 Backend도 같은 규칙을 최종 검증한다.
- **PROPOSED**: 수정 화면은 서버의 최신 데이터를 기준으로 하며, 저장 성공 응답을
  받은 뒤에만 동기화 완료로 표시한다.
- **PROPOSED**: 사용자가 값을 지운 것과 값을 보내지 않은 것을 구분할 수 있어야 한다.
- **OPEN**: 개체 이름 외 필수 항목, 종 코드 목록, 동시 수정 충돌 방식, 사진·캐릭터
  연결 규칙은 Android·iOS·Backend가 확정해야 한다.

이 결정 전에는 플랫폼별로 서로 다른 필수 필드나 종 코드를 하드코딩하지 않는다.

## 급여와 급여 거부 기록

- **PROPOSED**: 정상 급여와 급여 거부를 같은 기록 종류의 명시적 결과로 구분한다.
- 정상 급여가 추가·수정·삭제되면 남아 있는 정상 급여 기록 중 가장 최근 날짜를 기준으로
  다음 급여일을 다시 계산한다.
- 급여 거부 기록의 추가·수정·삭제는 마지막 정상 급여일을 바꾸지 않는다.
- **OPEN**: 같은 시각의 중복 기록 허용 여부, 미래 기록 허용 범위, 기록 수정 시 상태
  재계산 주체가 서버인지 앱인지 Backend와 제품 담당자가 정해야 한다.

## 탈피와 체중 기록

- **PROPOSED**: 탈피 기록은 발생 날짜·시각을 필수로 하고 메모는 선택으로 취급한다.
  시작/완료 구분이나 품질 상태가 필요하다면 별도 제품 결정으로 추가한다.
- **PROPOSED**: 체중은 전송·저장 시 단위가 명시된 양수 값이어야 한다.
- **PROPOSED**: 플랫폼 간 비교를 위해 서버의 기준 단위는 gram으로 통일하고, 화면에서
  다른 단위를 지원할 경우 입력값을 손실 없는 정밀도로 변환한다.
- **OPEN**: 허용 소수 자릿수, 최소·최대 범위, 지원 표시 단위와 반올림 규칙은 제품·
  Backend가 확정해야 한다.

단위와 정밀도가 확정되기 전에는 값만 전송하거나 플랫폼별 반올림을 적용하지 않는다.

## 조회와 삭제

- **PROPOSED**: 동일한 정렬 기준을 사용하도록 서버가 안정적인 순서와 페이지 정보를
  제공하고, 앱은 서버가 준 순서를 임의로 바꾸지 않는다.
- **PROPOSED**: 기록 저장·삭제 성공 후 해당 개체의 목록과 파생 급여 상태를 갱신한다.
- **PROPOSED**: 삭제 실패 시 화면에서 성공한 것처럼 영구 제거하지 않고 재시도 경로를
  제공한다.
- **OPEN**: 기본 정렬, 페이지 방식, 삭제 확인, soft/hard delete, 복구와 감사 보존
  정책은 Backend와 제품 담당자가 결정해야 한다.

## 날짜와 시간

- **PROPOSED**: 실제 시각이 중요한 기록은 timezone offset이 포함된 값을 서버에
  전달하고 서버는 일관된 기준 시각으로 저장한다.
- **PROPOSED**: 화면에는 사용자에게 적용된 시간대를 명확히 일관되게 사용한다.
- **OPEN**: 다음 급여일 계산이 사용자 계정, 개체 또는 기기 중 어느 시간대를 기준으로
  하는지와 여행·시간대 변경 시 처리 방식을 정해야 한다.
- **OPEN**: 부화일처럼 날짜만 의미가 있는 값과 급여처럼 시각이 필요한 값의 목록을
  Backend 계약에서 구분해야 한다.

시간대 정책이 확정되기 전에는 자정 경계 통합 테스트와 `DUE` 전환 구현을 완료로
간주하지 않는다.

## 빈 값과 잘못된 값

| 입력 | 공통 처리(제안) |
|---|---|
| 선택 필드 미입력 | `null` 또는 필드 생략 중 서버 계약에 정한 한 방식 사용 |
| 값 삭제 | 미전송과 구별되는 서버 계약 사용 |
| 공백뿐인 필수 문자열 | 제출 차단 및 해당 필드 오류 표시 |
| 알 수 없는 enum/code | 저장하지 않고 호환성 오류로 처리 |
| 0 이하 또는 파싱 불가 체중 | 제출 차단 |
| 유효하지 않은 날짜·시간 | 제출 차단, 원래 입력을 가능한 범위에서 유지 |

`null`, 생략, 빈 문자열의 정확한 의미는 **OPEN**이며 필드별 계약 없이 서로 변환하지 않는다.

## API 오류 시 공통 동작

- 인증 만료는 [인증 공통 계약](auth-contract.md)의 갱신·재로그인 흐름을 따른다.
- 검증 오류는 가능한 경우 관련 필드에 표시하고 사용자의 입력을 유지한다.
- 네트워크·시간 초과는 재시도 가능한 오류로 표시하며 성공으로 기록하지 않는다.
- 충돌 응답은 최신 데이터를 다시 확인하도록 안내하며 로컬 값으로 조용히 덮어쓰지 않는다.
- 서버 오류와 알 수 없는 응답은 일반 오류로 처리하고 원문에 포함될 수 있는 개인정보를
  로그나 사용자 메시지에 노출하지 않는다.

오류 응답 구조, 멱등성 키 지원과 재시도 가능한 작업의 범위는 **OPEN**이다.

## 설명용 JSON 예시

다음은 논의용 개념 예시일 뿐 실제 엔드포인트, 필드명 또는 서버 응답 계약이 아니다.

```json
{
  "example_only": true,
  "reptile_reference": "server-defined-id",
  "record_kind": "FEEDING",
  "feeding_result": "REFUSED",
  "occurred_at": "2030-01-15T18:30:00+09:00",
  "optional_note": null
}
```

실제 필드명, enum, 식별자 형식과 날짜 직렬화는 Backend 검토 후 확정한다.
