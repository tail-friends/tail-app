# 아키텍처

## 범위와 원칙

이 문서는 기능 구현 전 구조적 경계를 정의한다. Android는 Flutter, iOS는
Swift/SwiftUI로 각각 구현하고 동일한 Spring Boot 백엔드를 사용한다. 현재
확정되지 않은 API 계약은 정의하지 않는다.

## 저장소 경계

- `android-app/`: Android용 Flutter 애플리케이션과 Android 빌드 설정
- `ios-app/`: iOS 담당자 소유 영역
- `shared/`: 양 플랫폼이 합의한 계약·자료만 배치
- `docs/`, `.github/`: 공통 협업 영역
- 백엔드: 별도 저장소에서 관리

## Android 코드 방향

기능이 추가될 때 `lib/features/<feature>/` 아래에 화면, 상태, 도메인 규칙,
데이터 접근을 필요한 만큼만 둔다. 앱 전역 테마나 재사용 UI는 `lib/core/`에
둘 수 있다. UI는 업무 규칙을 직접 계산하지 않고, 업무 규칙은 Flutter에
의존하지 않는 테스트 가능한 Dart 코드로 유지한다.

상태 관리, 내비게이션, HTTP 클라이언트, 로컬 저장소는 요구사항과 API 계약이
확정된 Issue에서 선택한다. 초기 구축 단계에서는 특정 패키지를 선점하지 않는다.

## 핵심 도메인 경계

- 급여일: 마지막 정상 급여일에 급여 주기를 더한다. `안 먹음`은 정상 급여일을 갱신하지 않는다.
- 상태: `NO_RECORD`, `UPCOMING`, `DUE`, `OVERDUE`를 유지한다.
- 건강 경고: 기록 기반 참고 정보이며 진단으로 표현하지 않는다.
- 캐릭터: 속성 데이터, 행동 상태(`IDLE`, `WALK`, `CHASE`, `EAT`, `REACT`, `SLEEP`), 렌더러를 분리한다.
- 렌더러: 첫 버전의 2D 일러스트 구현을 데이터/행동에서 분리하여 향후 AI 실사풍 렌더러로 교체 가능하게 한다.

## 보안과 사진

사진 분석 전 사용자에게 목적을 안내한다. 원본 보관은 명시적 동의를 받은
경우에만 허용하고 삭제 경로를 제공한다. AI 또는 백엔드 인증키는 모바일 앱에
포함하지 않으며 서버를 통해 보호한다.

## 배포 전 결정

Android application ID, 서명키 관리, API 환경 분리와 스토어 메타데이터는
배포 전에 확정해야 한다. 현재 가정과 미정 항목은 `docs/open-questions.md`에서
추적한다.
