# Flutter Android 작업 규칙

- Dart 공식 스타일과 `flutter_lints`를 준수하고 `dart format`을 적용한다.
- 기능 코드는 기능 단위로 구성하되 실제 필요 전에는 빈 계층이나 추상화를 만들지 않는다.
- Widget은 표시와 입력 처리에 집중시키고 비즈니스 규칙은 테스트 가능한 Dart 코드로 분리한다.
- 프로젝트 전체에서 선택한 상태 관리 방식을 일관되게 사용한다. 새 방식 도입은 근거를 문서화한다.
- 공통 컴포넌트를 재사용하되, 한 번만 쓰이는 코드를 성급하게 추상화하지 않는다.
- API 전송 모델과 UI 표시 모델의 역할을 분리한다. 확정되지 않은 API 모델은 만들지 않는다.
- 인증키, 서명 정보, 개인정보를 소스나 로그에 포함하지 않는다.
- Android 작업 중 `ios-app/`을 생성하거나 수정하지 않는다. `shared/`, `docs/`, `.github/` 변경은 플랫폼 영향을 확인한다.
- 변경 보고에는 파일 경로와 변경 이유를 적는다.
- 완료 전 최소 `flutter analyze`와 `flutter test`를 실행하고, Android 설정 변경 시 가능한 경우 debug APK 빌드도 확인한다.
